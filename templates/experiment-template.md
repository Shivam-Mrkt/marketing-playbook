# Experiment template

Complete the design before launch, then append the result and decision after the outcome window. Preserve the original hypothesis so it cannot be rewritten to fit the result.

## Illustrative example: B2B SaaS

This completed directional pilot for fictional RelayDesk uses invented outcomes, not Shivam's results.

| Field | Completed example |
| --- | --- |
| Experiment name | Territory-specific demo page versus general product page |
| Problem | Search visitors may not see their territory-routing task addressed clearly |
| Hypothesis | A specific workflow explanation will improve qualified leads per eligible visitor |
| Audience | Eligible non-brand Search visitors seeking territory-routing software |
| Change | Territory message and sample workflow; same offer and form |
| Primary metric | Qualified leads ÷ eligible visitors |
| Secondary metrics | Form submissions, qualified share and cost per qualified lead |
| Guardrails | Form errors, contactability and comparable sales response |
| Assignment | Stable random visitor split; exclude staff and test records |
| Sample plan | Directional pilot of 1,000 eligible visitors per arm; insufficient basis for a definitive small-lift claim |
| Duration | Four-week exposure cap, then 14 days for qualification; if sample falls short, report that limitation |
| Stop rules | Stop for broken tracking or form failure; do not stop because one variant temporarily leads |
| Owner | Demand generation lead with analytics and sales reviewers |
| Result | Control: 20 qualified from 1,000 visitors. Treatment: 27 from 1,000. Rates 2.0% and 2.7%; observed difference 0.7 percentage points |
| Learning | Directionally promising, but limited outcomes do not establish a reliable lift |
| Next action | Review lead notes and design a separately declared, adequately sized test before rollout |

For a live confirmatory test, replace the pilot sample with a calculation based on baseline, minimum worthwhile effect and the chosen statistical approach. Do not simply inherit these illustrative numbers.

## Review checklist

- [ ] Problem → Hypothesis → Change → Metric → Test → Result → Learning → Next action is complete.
- [ ] Assignment, missing outcomes and external changes were checked.
- [ ] Counts and rates agree.
- [ ] Statistical claims use an appropriate analysis.
- [ ] Inconclusive results are recorded without a forced winner.
