# AI search

## Why it matters

Search journeys can include conventional results, AI-generated answers and conversations with LLM-based tools. A brand may be mentioned without receiving a click. Visibility therefore needs a broader observation method, but it still needs business relevance.

## Objective

Make expertise clear, accessible and accurately represented. Treat LLM visibility as something to observe and improve through useful information, not a guaranteed outcome from a special optimisation trick.

## Working framework

| Area | Practical action | Limit |
| --- | --- | --- |
| Entity understanding | Keep brand, product, category and company descriptions consistent | Consistency does not guarantee inclusion |
| Helpful content | Answer actual questions with clear scope and evidence | Length alone does not establish quality |
| Structured information | Use clear headings, tables and appropriate markup that matches visible content | No universal schema guarantees an AI citation |
| First-party expertise | Publish original methods, demonstrations and reviewed findings | Unverified claims remain weak evidence |
| Brand mentions | Earn relevant coverage through useful work and relationships | A mention count is not a causal ranking factor |
| Access | Check important pages can be found and read | Systems differ in retrieval and citation behaviour |

Google states that its established SEO practices apply to AI features and that no special additional optimisation is required for eligibility. This is Google-specific guidance, not a promise about all LLM products. [Google's AI features documentation](https://developers.google.com/search/docs/appearance/ai-features).

## Step-by-step process

1. Build a small set of realistic buyer questions across learning, comparison and selection.
2. Record the system, date, locale, exact question and relevant session conditions.
3. Note whether the brand appears, how it is described and which sources are cited.
4. Repeat observations; answers can vary. Keep the question set stable for comparison.
5. Fix inaccurate public product information and improve pages where genuine evidence is missing.
6. Track referral visits and qualified enquiries where observable. Ask buyers how they discovered the business as a separate signal.

## Illustrative example: B2B API company

Fictional ParcelBridge checks questions about shipment-status APIs. Some answers confuse event notifications with shipment creation. The team publishes a clear capability comparison and a reviewed workflow example. It then observes whether descriptions become more accurate; it does not claim the update will secure citations.

## Metrics and checklist

Use sampled mention rate, citation rate, description accuracy and identifiable qualified referral traffic. Always report the question set and sample size. These are observations, not total market share.

- [ ] Product descriptions are consistent and current.
- [ ] Expert contribution and evidence are visible.
- [ ] Structured information matches page content.
- [ ] Observation method is repeatable.
- [ ] No guaranteed visibility claims or manufactured mentions.

**Experiment idea:** improve one documented information gap and monitor a fixed question set against unrelated control questions. Treat changes as directional because answer systems also change.
