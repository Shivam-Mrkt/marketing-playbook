# Content clusters

## Why it matters

A cluster gives readers a coherent route through a subject. It is useful when each page answers a distinct question; publishing overlapping pages under a shared keyword does not create that value.

## Framework

Broad subject → Distinct buyer questions → Appropriate pages → Contextual links → Relevant next step

## Step-by-step process

1. Pick a subject the business has enough expertise to cover properly.
2. Map the questions by task: understand, compare, implement and evaluate.
3. Assign one preferred page to each task and review existing URLs first.
4. Build a hub that explains the subject and helps people choose a route.
5. Link supporting pages where the next question naturally occurs. Use descriptive anchor text.
6. Check whether multiple pages receive the same queries and satisfy the same intent. Consolidate only when the overlap is unhelpful.

## Illustrative example: B2B SaaS

| RelayDesk's fictional cluster | Distinct purpose |
| --- | --- |
| Lead routing guide | Explain the overall process |
| Round robin vs territory routing | Choose an assignment method |
| Routing rules checklist | Implement and check rules |
| Lead routing software | Evaluate RelayDesk's product |

The comparison links to the checklist when discussing implementation. The product page links to the guide for readers who need context. There is no requirement to link every page to every other page.

## Metrics and mistakes

Review useful movement between pages, relevant query coverage and qualified conversions across the cluster. Do not add page-level conversions together if the same person appears on several pages. Avoid creating a page for each trivial keyword variant or treating a cluster as a guaranteed ranking mechanism.

## Practical checklist

- [ ] Each page has a distinct job.
- [ ] Hub helps the reader choose a route.
- [ ] Links explain what the destination offers.
- [ ] Overlapping pages are reviewed with query evidence.

**Experiment idea:** add contextual links from established guides to one relevant comparison page. Monitor referral engagement and search discovery separately.
